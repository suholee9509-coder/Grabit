# Skill: figma-reverse-engineering (PM + frontend)

UI가 **Figma에 픽스(90%+)**된 프로젝트의 디자인-퍼스트 워크플로우. PM이 Figma에서 스펙을 *역설계*하고, frontend가 Figma MCP로 *픽셀-퍼펙트 퍼블리싱*한다.

> 원칙: **무엇 = Figma, 왜·스코프·데이터규칙 = 기획문서(`docs/source/`).** 충돌 시 무엇은 Figma, 왜·스코프는 문서가 이긴다. 디자인 *생성* ❌.

## A. PM — 역설계 (스펙 도출)

### A0. 구조 파악 + 인벤토리 (Sprint 0, 1회 — *먼저*)
1. Figma MCP로 전체를 훑어 **화면 계층·내비게이션·플로우·상태·컴포넌트 구조**를 파악(단순 목록 ❌ — 어떻게 연결·이동하는지까지). **이 구조가 유닛 절단의 1차 기준.**
2. `docs/design/README.md`에 **프레임 인벤토리**(프레임 → 화면/플로우 → 상태 → 단위) + Figma 링크 기록.
3. 기획문서(`docs/source/`)로 의도·스코프·데이터 규칙을 흡수. 충돌은 위 원칙으로 해소.

### A1. 단위 분해 (sprint-kickoff과 연동)
- **단위 = Figma 구조에서 절단**(기능 목록 ❌): 유닛 경계는 *A0에서 파악한 화면/플로우 구조*에서 나온다. 각 단위 = 화면 + 상태(빈/로딩/에러, *프레임에서 열거*) + 데이터 + 배선을 한 슬라이스로, 프레임에 매핑.
- **데이터 모델은 UI에서 역설계**: 폼 필드·리스트·상태·토글에서 엔티티/필드 도출 → 기획문서의 규칙으로 검증.
- 각 단위 `spec.md`는 **[docs/units/README.md](../../docs/units/README.md) 구조**로 작성 — **라벨드 L1 스토리(L1-a/b/c) + 각 Acceptance → L1-x 추적 + 대상 Figma 프레임 + `[fidelity]`(프레임 1:1)**. PM은 거기 링크된 **Oliver 레퍼런스 커밋(d88c638·bab64e4·현재 units/)을 직접 읽고 동일 스타일로** 쓴다. 무거운 유닛은 폴더 내 서브-spec 분할.
- **디자인 공백**(프레임에 없는 상태/엣지)은 *지금* 식별 → 사용자 디자인 결정 받거나 스코프 제외. (dev 작업 중 추측 ❌)

## B. frontend — 퍼블리싱 (픽셀-퍼펙트)

### B0. 디자인-시스템 추출 (선행 단위, 1회)
- Figma 스타일/변수/컴포넌트를 **추출** → `src/app/styles` 토큰(`--color-*`, `--space-*`, `--text-*`, `--radius-*`) → Command Center §5에 토큰 사전 기록. (모든 화면 단위의 의존)

### B1. 화면 단위 퍼블리싱 (goal-loop)
1. `spec.md`의 대상 프레임을 **Figma MCP로 연동** → 레이아웃·색·간격·타이포·상태를 *정확 값*으로 추출 (눈대중 ❌).
2. FSD로 구현, **§5 추출 토큰만** 사용. 빈/로딩/에러 상태는 *프레임대로*.
3. 셀프 `/design-review`로 **프레임 대비 충실도**(1:1) 검증 → gap을 측정값으로 좁힘.
4. 프레임에 없는 것 발견 → 추측 ❌ → `status.md` escalation (디자인 공백).

## C. 검증
- frontend 셀프 `/design-review`(충실도) → QA `/design-review` 프레임 대비 fidelity 재검증 → **★ 게이트 ⓒ 충실도 사인오프**(사용자가 픽셀-퍼펙트 일치 확인).
