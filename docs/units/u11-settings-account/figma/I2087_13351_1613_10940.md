## 3. u11 계정메뉴/수신함 부착 지점 (★ 핵심 산출물)

### 진입점 2종 (이미 sidebar에 존재 — u11이 핸들러를 와이어링)
1. **수신함 nav** — `sidebar.tsx` line 65 MENU `inbox` 항목. 클릭 시 `onMenuSelect('inbox')` 발화(line 110). → **u11 수신함/알림 화면의 진입점.** u11은 `activeMenu='inbox'`일 때 라우팅될 수신함 페이지를 붙인다.
2. **GNB 프로필 카드** — `sidebar.tsx` line 160–182 `profileWrap`/`profileCard`. 클릭 시 `onProfileClick()` 발화(line 162). → **u11 계정메뉴(드롭다운/팝오버)의 트리거.** 이 카드에 계정메뉴(설정·프로필수정·로그아웃·탈퇴)를 앵커한다.

### 부착 방식 (sidebar 위젯 비훼손)
- sidebar 위젯의 `index.ts`는 `Sidebar` 컴포넌트와 props 타입만 공개(NavItem/icons는 비노출). **u11은 sidebar 내부를 수정하지 않고**, 상위(app/page 레이어)에서 두 콜백 props를 와이어링:
  - `onMenuSelect`: `inbox` 키 → 수신함 라우트.
  - `onProfileClick`: → u11 계정메뉴 표시(앵커 = 프로필 카드 DOM).
- 계정메뉴는 sidebar 외부 신규 컴포넌트(`features/account-menu` 등)로 만들고, 프로필 카드를 anchor로 포지셔닝. **sidebar 위젯 코드 미접촉.**

### 디자인 공백 경고 (★ 카디널 ②)
- **나머지 화면(계정메뉴·설정·프로필수정·로그아웃·탈퇴·수신함·알림)은 전용 Figma 프레임 없음 = 디자인 공백.** 추측 비주얼 금지.
- 구현 시 **u0 파운데이션 tokens.css + shared/ui 컴포넌트와 1:1**로만 조립(발명 금지·하드코딩 HEX 금지). 위 §2의 토큰 매핑이 이 진입점에서 검증된 파운데이션 일관 기준 — 동일 토큰 팔레트(text-secondary #B4B4B4 · text-primary #FAFAFA · surface-200 #242424 · radius-md 8 · space-4/5 · nav-item 32 · Body3 14/160%/-2%)를 그대로 따른다.
