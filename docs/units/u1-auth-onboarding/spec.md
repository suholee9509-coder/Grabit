## L1 User Story  (검증의 north star — 각 인수기준이 여기로 추적된다)
- **L1-a** As a 비회원, 로그인 진입 화면에서 **소셜 로그인**(Google/Kakao — ADR-0001 확정 제공자)으로 인증을 시작하면 OAuth 시스템 다이얼로그(`2087:6043` = 제공자 화면, DS 대상 외)를 거쳐 인증 세션이 만들어진다.
- **L1-b** As a 신규 회원(온보딩 미완료), 인증 직후 **프로필 4단계 온보딩**(① 직업 단일 → ② 연차 단일 → ③ 관심분야 복수+직접입력 → ④ 목표 단일)을 stepper(4세그먼트)를 따라 진행하며, 각 단계에서 이전/다음(마지막=완료)으로 이동하고 입력값이 누적된다.
- **L1-c** As a 온보딩을 마친 회원, "완료"를 누르면 프로필(public 코호트=직업+연차, 관심분야, 목표≈현재상황)이 저장되고 **홈으로 진입**하며, 진입 시 **크롬 확장 설치 안내 모달**(`2087:9468`)이 노출된다.
- **L1-d** As a 회원, 확장 설치 모달에서 "설치하러 가기"(웹스토어 이동) 또는 "나중에 하기"(닫고 홈 사용)를 선택할 수 있다.
- **L1-e** As a 기존 회원(온보딩 완료), 재로그인하면 온보딩을 다시 거치지 않고 바로 홈으로 진입한다. (온보딩 완료 게이팅)

**Production acceptance (관찰가능):** prod-like 환경에서 ① 비회원이 로그인 화면에서 Google/Kakao 버튼을 눌러 OAuth를 완료하면 세션 생성, ② 신규 회원은 직업→연차→관심분야→목표 4단계를 stepper 따라 진행(이전/다음·완료, 관심분야 1~5 선택+직접입력), ③ "완료" 시 `profiles`에 코호트·관심분야·목표가 저장되고 홈으로 리다이렉트 + 확장 설치 모달 노출, ④ 모달의 두 CTA(설치하러 가기=웹스토어 새 탭 / 나중에 하기=닫기)가 동작, ⑤ 기존 회원 재로그인은 온보딩 스킵하고 홈 직행. QA가 e2e로 각 L1을 재현. **요금제/구독 모달·결제·페이월·연간 플랜·AI·대시보드 탭은 이 플로우에 존재하지 않는다.**

### Acceptance criteria  (스토리에서 도출 · 관찰가능 · 각 항목 → L1-x 추적)
**BE** (owner=both — u0b 위 additive)
- [behavior] **OAuth 인증**: Supabase Auth로 **Google + Kakao** OAuth(ADR-0001) — 콜백 처리, 세션 발급, `chrome.storage`/웹 세션은 ADR-0001 흐름. JWT 검증은 u0b/Supabase 계약 재사용. 이메일/비번 로그인 ❌(미구현). Naver 후순위(스텁/숨김 — E1 결정 따름). → L1-a
- [behavior] **프로필 저장 RPC/정책**: 온보딩 "완료" 시 본인 `profiles`에 직업(단일·필수)·연차(단일·필수)·목표≈현재상황(단일·필수)·관심분야(복수 최소1·최대5, 직접입력 항목 포함) 저장. public 코호트(직업+연차)와 private(auth·관심사·목표)는 ADR-0002 #6대로 노출 경로 분리. RLS=본인만 쓰기. → L1-c
- [behavior] **온보딩 완료 게이팅**: `profiles`에 온보딩 완료 플래그(또는 코호트 NOT NULL 판정). 인증 후 미완료=온보딩 라우트, 완료=홈. → L1-b/e
- [negative] 미인증/만료 토큰 401 · 타 user 프로필 쓰기 차단(RLS) · 관심분야 0개 또는 6개+ 거부(서버 검증) · 단일선택 필드(직업·연차·목표) 누락 시 완료 거부 · 직접입력 관심사 공백/XSS/길이초과 무해화 · 미완료 코호트의 sanitized 공개집계 노출 0 · OAuth 콜백 실패/취소 처리(에러 라우팅, 미완성 세션 잔류 ❌).
**FE** (owner=both)
- [behavior] 로그인 화면에서 Google/Kakao 버튼 → OAuth 시작 → 콜백 → (신규)온보딩 / (기존)홈. → L1-a/e
- [behavior] 4단계 stepper 플로우: 직업(단일칩)→연차(단일칩)→관심분야(복수칩 1~5 + 직접입력)→목표(단일칩). 이전/다음 네비, 마지막=완료. 단계별 선택값 누적·유지(뒤로 와도 보존). stepper 세그먼트 active 반영. → L1-b
- [behavior] "완료" → 프로필 저장 → 홈 리다이렉트 → 확장 설치 모달 자동 노출. → L1-c
- [behavior] 모달: "설치하러 가기"=크롬 웹스토어 새 탭(URL은 E4 결정) · "나중에 하기"=모달 닫고 홈. (모달은 1회/재노출 정책 E5) → L1-d
- [negative] 다음/완료 비활성: 필수 단일 미선택 시 다음 차단 · 관심분야 0개 시 다음 차단 · **관심분야 6번째 선택 차단**(칩 비활성 또는 토스트 — 디자인 공백, E2) · 직접입력 빈/공백 무시·중복 방지·길이 제한 · 미인증 상태로 온보딩/홈 직접 접근 시 로그인으로.
- [non-regression] u0 앱셸/GNB(홈·검색·라이브러리·수신함 4탭 — FD1, 대시보드 탭 없음)·기존 라우팅·u0b RLS/sanitized view 안 깨짐. u0c stepper·소셜버튼·칩 컴포넌트 비주얼 보존.
- [state] **로그인**: OAuth 진행 중 버튼 펜딩/스피너(파운데이션) · 콜백 처리 중 로딩. **온보딩**: 단계 전환 중 펜딩 · 완료 저장 중 버튼 펜딩. **모달**: 표시/숨김, 설치 이동 중 펜딩. **에러**: OAuth 실패/취소=에러 안내+재시도(로그인 복귀) · 프로필 저장 실패=토스트+재시도 · 네트워크오류 처리. *로그인 에러·Kakao/Google 실패·약관 거부 등 전용 프레임 없음 → 파운데이션으로 일관 채움.*
- [fidelity] 대상 6프레임과 1:1: 로그인 `2087:8221`(소셜버튼 radius6/`#1B1B1B`·CTA `#66FF4B`·divider·약관·프로모 패널) · 직업 `2087:8476` · 연차 `2087:8726` · 관심분야 `2087:8968`(칩 그리드·직접입력) · 목표 `2087:9228` · 모달 `2087:9468`(타이틀·체크3행·CTA2종) — 토큰·간격·정렬·타이포·**stepper(40×4)**·칩 selected/rest 상태가 프레임/ u0c와 동일. → L1-b/c/d
