## L1 User Story  (검증의 north star — 각 인수기준이 여기로 추적된다)
- **L1-a** As a 회원, `라이브러리` 진입 시 내가 클립한 **모든 컨텐츠 리스트(전체 폴더)**를 카드 그리드(썸네일·제목·태그·`N개` 그랩수)로 보고, 좌측 `내 라이브러리` 사이드바(내 컨텐츠/북마크 탭·폴더 트리)와 상단 `라이브러리` 헤더(설명·`컨텐츠 추가` 버튼)로 라이브러리 전체를 한곳에서 관리한다 — so that 클립한 컨텐츠가 흩어지지 않고 다시 찾고 복습된다.
- **L1-b** As a 회원, 우측 패널의 **`컨텐츠` / `인사이트` 탭**을 전환해, 컨텐츠 탭(컨텐츠 카드 그리드)과 인사이트 탭(인사이트=내 메모 카드 그리드: 썸네일+메모 발췌)을 오갈 수 있다.
- **L1-c** As a 회원, **출처(소스)별 카운트 필터**(전체 32·Youtube 16·Long Black 8·Medium 6·EO planet 2·Publy 2 …)로 컨텐츠를 출처별로 좁히고, 정렬(최신순…)로 순서를 바꾼다 — 선택된 출처 칩은 채움(#FAFAFA)으로 강조된다.
- **L1-d** As a 회원, **폴더**(예: `창업가 정신`·`피그마 실습 강의`·`디자인 트렌드`)를 폴더 카드(160×160·`N개의 컨텐츠`) 또는 좌측 폴더 트리에서 선택해 **폴더별 컨텐츠 리스트**로 진입하고(헤더가 폴더명·`N개의 컨텐츠`로·브레드크럼 `전체 폴더 / <폴더명>` 노출), `전체 폴더` 드롭다운/좌측 트리 토글로 폴더 간 이동한다.
- **L1-e** As a 회원, 폴더를 **생성(최대 20개)·이름변경·삭제**하고, 컨텐츠를 **다중선택해 폴더로 이동**한다.
- **L1-f** As a 회원, 카드를 클릭하면 **콘텐츠 상세(u4 재사용 — 컨텐츠[시청 정보/원본 소스]·인사이트 탭)**로 진입해 재소비한다.

**Production acceptance (관찰가능):** prod-like(로컬 Supabase + 시드)에서 회원이 `/library` 진입 → 내 클립 컨텐츠가 전체 폴더 그리드로 뜨고, `컨텐츠`↔`인사이트` 탭 전환·출처 카운트 필터·정렬이 동작하며, 폴더 카드/좌측 트리/`전체 폴더` 드롭다운으로 폴더별 뷰(헤더·브레드크럼 갱신)에 진입하고, 폴더 생성/이름변경/삭제 모달과 다중선택→폴더 이동이 본인 데이터에만 반영되며(타 user 폴더/클립 누출 0), 카드 클릭이 u4 상세로 이동한다. 빈(폴더0/컨텐츠0)·로딩·에러는 u0c 파운데이션 표면으로 일관 렌더된다. QA가 위 상태들을 e2e 재현. AI 노트 탭·아티클 경로·결제 표면 없음.

### Acceptance criteria  (스토리에서 도출 · 관찰가능 · 각 항목 → L1-x 추적)
**BE** (owner=both — u0b 락 계약 위에서 *folders/이동 신규 배선*, in-flight 흡수)
- [behavior] **라이브러리 리스트**: 본인 클립이 부착된 content를 카드 표면(content_id·제목·썸네일·태그·그랩수·출처)으로 조회. RLS: 본인 행만(읽기=본인). 정렬 = 최신순(기본)/오래된순/클립 많은 순(기획 §5.1.1) 파라미터. → L1-a/c
- [behavior] **folders 엔티티(신규 마이그레이션)**: `folders`(user_id, name, created_at) + **클립↔폴더 부착**. ★ADR-0002 #8·DM2 판정 = **folder=클립 부착(`clips.folder_id`)**(클립 모달이 폴더+태그 동시 설정·u3/u6와 일관). 한 콘텐츠의 클립이 서로 다른 폴더면 콘텐츠가 복수 폴더에 표시될 수 있음(콘텐츠-단일폴더로 조일지는 [ESCALATION DM2] 확정). 폴더별 카운트(`N개의 컨텐츠`) = 해당 폴더 부착 클립의 distinct content 수. → L1-d
- [behavior] **폴더 CRUD**: 생성(이름·**최대 20개 서버 제약**)·이름변경·삭제(soft-delete, ADR-0002 #9 — 삭제 시 클립의 folder_id 처리: NULL 해제 또는 전체 폴더로 환원). 본인 폴더만(RLS 쓰기=본인). → L1-e

## ★ ESCALATION 후보 (PM 결정 필요 — 착수 전/초기 턴)

### DM2 — folder ↔ 클립/콘텐츠 부착 모델 [ADR-0002 #8 · command-center DM2]
**프레임 실측:** 폴더 카드/좌측 트리/폴더별 뷰는 폴더 단위로 **컨텐츠**를 묶어 보여준다(`32개의 컨텐츠`·`72개의 컨텐츠`). 클립 생성 모달(u3/u6, 프레임 `2087:33548`/`2074:88421`)은 클립 저장 시 **폴더+태그를 동시 설정**한다 → 부착 단위가 *클립*임을 시사.
**핵심 충돌:** 부착 대상이 (A) **클립**(`clips.folder_id`)이냐 (B) **콘텐츠**(content↔folder 단일/다대다)냐. (A)면 한 콘텐츠의 클립들이 서로 다른 폴더에 있을 수 있어 콘텐츠가 **복수 폴더에 표시**될 수 있고, 폴더별 카운트는 "distinct content"로 집계해야 함. (B)면 콘텐츠가 단일(또는 명시적 다중) 폴더에 고정.
**판정(제안·잠정 채택):** ADR-0002 #8 + DM2 잠정값대로 **(A) folder=클립 부착(`clips.folder_id`)** — 클립 모달의 "폴더+태그 동시 설정"과 일관, u3/u6 데이터패스 단일화. 폴더별 뷰는 distinct content로 집계.
**PM에게 묻는 결정 1개:** *folder를 (A) 클립 부착(콘텐츠 복수 폴더 가능)로 둘지, (B) 콘텐츠-단일폴더로 조일지.* (B) 선택 시 클립 모달 UX(콘텐츠당 1폴더 강제)·마이그레이션 영향 동반 확정 필요. 미결 시 (A)로 진행(reversible).
